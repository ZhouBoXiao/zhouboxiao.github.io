  - **UB-Software-Reference-Design-for-OS-2.0-zh.pdf（57 页，83 条目录）← 本文主线**，
    结构：2 架构 / 3 设备管理 / 4 内存管理（含 UBTurbo）/ 5 通信（URMA·URPC·UMS）/ 6 虚拟化 / 7 RAS。
  - 3-灵衢内存池化（6 页）、5-灵衢设备虚拟化（9 页）、7-灵衢系统高阶服务（15 页）——峰会胶片，
    文字少、图多，提取后基本只剩要点，但**量化收益数字只在这里**（UBTurbo 分级内存对比、
    Redis/Memcache/Keydb 性能、UBSocket +100%、集群碎片 25%、超大虚机 3T 等）。
- 关键结论（写文章时的抓手）：
  - 访存模型 Host-Device → **User/Home**；ummu driver 管 Home 侧、UB Decoder driver 管 User 侧，路由靠 UBFM。
  - 池化 = `obmm_export` 产出 {EID,UBA,TokenID} → UBPRM 补 {src EID,scna,dcna} → `obmm_import`，
    上线形态二选一：**NUMA node（应用零修改）/ char device（mmap，共享场景）**。
  - Ownership 三态（Invalid/Read/Write）+ Clean/Invalidate 两动作，**无跨节点硬件一致性**。
  - 设备管理：UBRT → ubfi/ubus → `ub_bus_type`/`ub_entity`/`ub_driver`；另有服务总线按 serviceID 匹配。
  - 虚拟化八件套：UB_MGR / vUMMU / vBusController / vUBDev / UB Firmware(edk2) / vfio-ub / KVM USI / iommufd；
    **虚机必须配大页**（UMMU 权限表要求内存连续）；BusController port 上限 256（8-bit index）。
  - RAS：A/B/C 三类错误 + 五条路径；sysSentry 劫持 OOM/Panic/reboot，UBPRM 决策，节点复位前要先把借出内存迁走。

## 灵衢学习笔记（三）：系统高阶服务 / 可靠性 / 编程编译 / 管控运维（收尾篇）

  篇一、篇二开头均已补「姊妹篇」指引。至此 11 份 PDF **全部读完**。
- 本轮素材：
  - UB-Service-Core-SW-Arch-RD-2.0-zh.pdf（26 页 / 39 条目录）← 本篇主线，五大组件各自的架构与场景。
  - UB-Mgmt-OM-SW-Arch-and-IF-RD-2.0-zh.pdf（28 页）← 只讲接口，PoD/Server 两形态 + Redfish/NETCONF/SNMP/IPMI 矩阵。
  - 6-超节点可靠性关键技术（8 页）、8-超节点编程编译关键技术（10 页）← 胶片，数字密集。
- 关键结论：
  - UBS Engine = UBPRM 的一种实现；内部 EngineBase / uCache / RMRS / VirtAgent；去中心化 N-1 高可用。
  - UBS Mem 四语义：MemFabric（统一编址）/ SHMEM（C2C 或 D2D 共享）/ MemCache（弱一致高带宽，KVCache）/ MemStore（强一致低时延，金融）。
  - UBS Comm 四特性：**HCOM / Socket / HCAL / RoUB**（HCAL = 异构通信加速库，插件接入 NIXL/Transfer Engine；
    峰会材料里的 UBSocket 与 ROUB 在规范里叫 Socket 与 RoUB，写文章时要对应上）。
  - 可靠性：六类故障点（①内存颗粒 ②UMMU ③借出方 UB 控制器 ④整机 panic/掉电 ⑤UB 链路 ⑥本端 UB 控制器），
    核心是「提供方故障扩散到使用方」；指标：通知 <100ms、上线 10ms/GB、回迁 8GB/s、虚机恢复 <1s（实测 0.788s / 3.4s）。
  - 编程编译：Matrix C++（bisheng::async/future/partitioned_vector/execution::supernode）+ 毕昇编译 + 运行时，
    存量多线程应用迁移 <1 周；开源 gitee.com/openeuler/llvm-ub（3.5KLOC → 15KLOC → 5KLOC）。
  - 管控运维：UBM（拓扑/地址/路由/SLA，北向 NETCONF·RESTCONF·SNMP·Telemetry）/ BMC（Redfish 1.20.1·IPMI 1.5-2.0）/
    PoDManager（框级统一出口）/ MindCluster（AI 任务）。PoD 形态下柜内 BMC+UBM 不对外，统一走 PoDManager。
